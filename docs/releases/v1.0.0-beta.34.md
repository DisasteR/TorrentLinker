# TorrentLinker 1.0.0-beta.34

Cette bêta laisse un reverse proxy authentifier le propriétaire de l’interface web, et
rouvre les listes de lecture depuis le menu du lecteur.

## Interface web

- **Connexion par un reverse proxy** : un proxy qui authentifie déjà les utilisateurs
  (Traefik, Caddy, nginx…, par forward auth vers Authentik ou par authentification
  basique) peut remplacer le mot de passe de l’interface web. Définissez
  `TL_WEB_AUTH=proxy` et l’adresse du proxy dans `TL_TRUSTED_PROXIES`. Seules ces
  adresses agissent comme le propriétaire ; les autres reçoivent `403`, et les en-têtes
  transférés sont ignorés. Le serveur refuse de démarrer sans proxy de confiance, ou si
  `TL_WEB_AUTH` vaut autre chose que `password` ou `proxy`. Les agents et l’extension
  gardent leurs propres jetons. Voir « Connexion par un reverse proxy » dans le guide
  Docker, et `deploy/compose.traefik.yaml` pour Traefik. Contribution de DisasteR
  ([#62](https://github.com/Vietnoirien/TorrentLinker/pull/62)).

## Médias

- **Files et listes de lecture** : l’entrée « File et playlists » du menu du
  lecteur ouvre de nouveau le panneau. Elle levait une erreur, ce qui empêchait d’y
  supprimer une liste.

## Validation et limites

Les tests web, de l’extension et du navigateur passent avec le mode proxy. L’image a été
testée derrière Traefik 3.6 avec authentification basique sur un réseau Docker dédié :
les requêtes qui contournent le proxy, y compris avec un en-tête `X-Forwarded-For`
usurpé, reçoivent `403`, et le contournement des jetons ne laisse passer que `/mcp` et
les chemins de l’extension. Le forward auth d’Authentik et la partie TLS de l’exemple
n’ont pas été testés. Cette version reste une bêta.

## English

This beta lets a reverse proxy sign the Web UI owner in, and reopens playlists from the
player menu.

- **Reverse-proxy sign-in**: a proxy that already signs users in (Traefik, Caddy,
  nginx…, through Authentik forward auth or basic auth) can replace the Web UI password.
  Set `TL_WEB_AUTH=proxy` and the proxy's address in `TL_TRUSTED_PROXIES`. Only those
  addresses act as the owner; any other gets `403`, and forwarded headers are ignored.
  The server refuses to start without trusted proxies, or when `TL_WEB_AUTH` is anything
  but `password` or `proxy`. Agents and the companion keep their own tokens. See "Sign in
  through a reverse proxy" in the Docker guide, and `deploy/compose.traefik.yaml` for
  Traefik. Contributed by DisasteR
  ([#62](https://github.com/Vietnoirien/TorrentLinker/pull/62)).
- **Queue and playlists**: the player menu's "Queue & playlists" entry opens the panel
  again. It raised an error, which made deleting a playlist impossible.

The web, companion and browser tests pass with proxy mode. The image was tested behind
Traefik 3.6 with basic auth on a dedicated Docker network: requests that bypass the
proxy, including with a spoofed `X-Forwarded-For`, get `403`, and the token bypass lets
through only `/mcp` and the companion paths. Authentik forward auth and the TLS part of
the example were not tested. This is a prerelease; the stable release remains 0.12.2.
